High Level Overview

Twilio LiveKit Media Streams Call Handoff Blueprint

This blueprint shows how to let a LiveKit voice agent handle the first part of a phone call over Twilio Media Streams, then hand the live caller back to Twilio routing when the agent needs help, a human, or another destination.

Open GitHub Repo
Core idea: contain, decide, hand off Voice + AI + routing

What It Is

A call handoff pattern built on Twilio Media Streams

The blueprint connects Twilio Programmable Voice to LiveKit using the LiveKit Twilio Connector and <Connect><Stream>, passes the original Twilio parent call SID into the LiveKit room as connector participant attributes, and gives the LiveKit agent a tool that can update that original call when escalation is needed. The caller stays on the live phone call while Twilio decides the next route, whether the call started inbound directly on a number or inside a Studio Flow.

Containment

Let AI try first

LiveKit handles the real-time agent experience, including speech, reasoning, and self-service. Twilio stays ready to take the call back when the agent cannot complete the job.

Control

Keep routing in Twilio

The handoff updates the original Twilio call resource, so the next destination can be Studio, TaskRouter, Flex, another voice app, a dial target, or a conference.

Context

Carry the handoff summary

The agent sends intent, summary, and optional Memory identifiers back to Twilio so a downstream route or human agent can see what happened before escalation.

This blueprint uses LiveKit Twilio Connector and Twilio Media Streams. For the SIP-based version, see twilio-livekit-sip-call-handoff-blueprint. LiveKit Twilio Connector is currently in beta, so treat connector-specific behavior as subject to change.

This blueprint is a proof-of-concept reference implementation, not a production drop-in. Treat it as a starting point for the architecture and adapt routing, authentication, prompts, observability, security, and compliance controls to your use case.

Why It Is Useful

It separates the AI runtime from the routing decision

Teams often want to experiment with a specialized voice AI provider without rebuilding the rest of their contact center, and without standing up SIP trunks or dispatch rules. Media Streams keeps the transport inside Twilio's existing voice stack: LiveKit runs the agent, while Twilio continues to handle voice numbers, inbound and outbound call control, Studio journeys, TaskRouter queues, Flex tasks, and post-call context.

1

Preserve call control

Twilio updates the original live call, so the handoff can return to Studio, enqueue into TaskRouter, or route elsewhere without losing the parent call relationship.

2

Pass useful context

LiveKit connector participant attributes carry the parent call SID, handoff ID, call direction, caller number, and optional Memory identifiers into the agent session, and back out on escalation.

3

Route with Twilio

Use Studio for journey control, Flex for the tested agent experience, TaskRouter for another queue, or custom TwiML for a different destination.

When to use

Use it when escalation is part of the customer journey.

Use this blueprint when the LiveKit AI agent should solve common voice intents first, but needs a controlled fallback for account access, billing, compliance, complex support, or explicit requests for a person, and when you prefer Media Streams over running a SIP trunk.

It is especially useful when your Twilio number already starts in Studio, when Flex should receive structured task attributes, when routing logic needs to stay in TaskRouter, or when optional Twilio Memory should give LiveKit prior customer context. The first milestone focuses on inbound direct and inbound Studio; outbound calls started from Twilio or Studio can be added on top once inbound is working end to end.

How It Works

Three routing patterns, one parent-call update

The same LiveKit tool contract can hand the caller back to Studio, TaskRouter, or another TwiML-controlled destination. The difference is the Twilio Function URL and TwiML instruction used after escalation. Media Streams is the transport that carries the audio between Twilio and LiveKit in every pattern.

Shared call lifecycle Twilio Functions + LiveKit Twilio Connector
Twilio Voice Caller reaches a Twilio number, direct or through Studio.
LiveKit agent Twilio connects the live call over <Connect><Stream>.
Escalation tool Agent sends summary and parent call identifiers to Twilio.
Twilio routing Studio, TaskRouter, or custom TwiML receives the caller.

Pattern A: Studio return

Best when Studio owns IVR, branching, reporting, or Send to Flex.

  • /studio_voice Calls ConnectTwilioCall and streams the caller to LiveKit.
  • /studio_escalate Redirects the live call back to the Studio Flow with FlowEvent=return.
  • Studio resumes on the TwiML Redirect return transition.
  • Send to Flex creates the human-agent task.

Pattern B: TaskRouter enqueue

Best when you want the smallest direct handoff to Flex or another TaskRouter-powered contact center.

  • /voice Calls ConnectTwilioCall and streams the caller to LiveKit.
  • /escalate Updates the parent call.
  • <Enqueue> Twilio returns task attributes.
  • TaskRouter routes the voice task to an agent.

Pattern C: Generic TwiML route

Best when escalation should continue into a custom Programmable Voice app, a phone number, or a conference flow.

  • /voiceor/studio_voice Streams the caller to LiveKit through the connector.
  • The escalation tool posts summary and call identifiers to Twilio.
  • Your Function updates the parent call with custom TwiML.
  • Twilio continues the live call through your chosen route.

Optional Platform Layer

Memory and Intelligence can sit on top

Conversation Memory is optional. When enabled, Twilio can resolve a customer profile before dialing LiveKit and pass Memory identifiers into the agent session as connector participant attributes. The agent can then recall relevant prior observations, summaries, preferences, or open issues.

Orchestrator

Capture conversations

Conversation Orchestrator is the capture and configuration layer that groups voice and messaging interactions into normalized conversations.

Memory

Recall customer context

Memory stores and retrieves customer context across sessions and channels, helping the LiveKit agent avoid making callers repeat what already happened.

CINTEL

Analyze conversations

Conversation Intelligence is independent from Memory, but it can attach to the same Orchestrator-captured conversations for real-time or post-call analysis.
